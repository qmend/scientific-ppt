# scientific-ppt

Create a coherent presentation from the user's evidence and purpose. This Skill combines **Agent semantic planning** with a deterministic Python execution engine. A topic alone requires researched or user-provided facts; the CLI does not invent a lecture or summarize a paper intelligently by itself.

## Workflow

1. Read [the style guide](references/style_guide.md) and [content planning](references/planning.md). Establish audience, purpose, source provenance and uncertainty from the request. Infer routine choices. The default 4:3 style uses a pale background, burgundy title band and Chinese serif body text. The bundled [PowerPoint master](assets/template.pptx) provides cover, content and closing layouts. Plan the content and slide geometry for the specific deck.
2. Read the source material, including figures and tables. Use `extract` for a text aid; PDF/DOCX extraction does not recover figure semantics or complex tables. For a new reference deck, render **all** slides and inspect structure before changing tokens; follow [reference analysis](references/reference_analysis.md).
3. Write a deck JSON matching [the schema](references/deck.schema.json), following [schema usage](references/schema_usage.md). Plan the narrative and select evidence, figures, editable graphs and tables. Preserve data, units, original LaTeX and sources. Allow page count to increase for readability. For a system or method, first plan a complete, well-aligned, full-width figure suitable for spoken explanation. Reorganize it before splitting; add detail slides only if it remains unreadable at presentation size. Choose tables for precise lookup and charts for trends, distributions and larger datasets; pagination is a capability, not a content quota.
   Include a cover, vertical agenda list and closing page. Read [the fixed opening and closing style](references/bookends.md) and reuse [the bookend blocks](assets/bookends.json), based on the Mamba example. Cover fields are 汇报人、指导教师、日期, in that order, in a narrow, centered, transparent borderless table with left-aligned values; use xxx for missing values. The closing page contains THE END above 敬请指正. Set bottom-right page numbers to 18 pt and omit them on the first and last slides. On the cover and closing pages, place the thin header rule just below the centered English text. Place references on a dedicated page. Start references and prose directly below their title bars. Develop prose with a concrete example or explanation where the topic needs it.
   Chinese narrative pages should feel about 75–80% full within the usable body area, with compact, top-aligned, first-line-indented paragraphs. Develop the same topic with supported explanations and examples; do not inflate paragraph gaps to simulate density. Follow the narrative-density guidance in [the style guide](references/style_guide.md#中文叙述页密度与出处). On every slide type, put source details and section/page locators in PowerPoint speaker notes; do not add visible bottom source lines.
   Keep topics on separate pages. Set all table cells in bold, including data rows. For multipage tables, fill the available content height on every page that has a continuation. Use natural row heights on the final page and on single-page tables. Repeat the header and put the caption on the first table page. Keep table explanations on separate slides.
   Before defining figure blocks, read [figure design and tool selection](references/figure_tools.md). Use Drawlib for research methods and retain the actual intermediate representations, branches, joins and feedback. Align peer nodes, group headings and ports before styling arrows. Choose the figure aspect ratio by structure: try a wide layout for continuous horizontal sequences and a more compact layout for aligned branches or layers. Compare legibility at the intended paper column width or within the slide body area, preserving aspect ratio. On a standalone wide-figure slide, vertically center the figure and its caption together in the usable body area. Use group outlines only when they clarify membership. Align peer group boundaries and use one group-border system per figure: stronger colored solid outlines, or dashed outlines. Omit unnecessary or unalignable group boxes; place labels near their objects. Use modest corner rounding for selected nodes and groups, following the Nezha examples in the guide. Use sharp triangular tips and flat ends on thin connectors. Mix solid, dashed, outlined and colored arrows as the relationships and their importance require. Trim excess canvas margins and tighten unused space inside groups before placing the figure on a slide. Check the arrow body, hollow interior and dash gaps at slide size. Route edges directly where possible and use short bends or gentle curves to avoid labels. Inspect every arrow and label at output size. Use simple, consistent icons beside nodes or data-flow arrows according to meaning. Figure labels use regular weight. Balance compact legends above or below the plot or aligned right. Generate and inspect each bespoke figure before placing it as an `image` block. Use Matplotlib or a specialist plotting library for data figures, and supported native PowerPoint charts when the data needs to be edited in PowerPoint. Preserve contrast, axis units, numeric positions and measured points.
   Use white boxes for flowchart steps and keep editable source when available. Use SimHei title bars and bold SimSun slide body text, including bullets and callouts; this bold rule does not apply to text inside figures. Use blue or burgundy red only for a meaningful term or short phrase that helps readers find a key mechanism, distinction, or conclusion. Keep numbers, standalone letters and symbols, repeated terms, and routine labels in the default body color. See [schema usage](references/schema_usage.md) for inline colors. Use native bullets for parallel conditions, method points, evaluation dimensions and result findings. Bold subheadings alone do not count as a list. Align supporting explanations with the heading text after the bullet. Vary circle/square, filled/hollow, red/black bullet symbols by section, consistently within each list. Keep narrative paragraphs, captions, tables and numbered agendas in their own formats. Use a few pale blue/yellow/green panels with varied linear/radial gradients mainly for body text. Include one or two segmented, first-line-indented narrative pages when appropriate and use a few inline highlights to guide reading through their main ideas. Figure captions go below figures and initial table captions above tables, centered in black. Give equations numbers and explain symbols in body text. Read [the detailed style guide](references/style_guide.md) before composition.
4. Use the Skill's own `.venv` interpreter. If absent, follow [installation](references/installation.md). Run `doctor`, then `validate`, then `build`. The builder loads the bundled master automatically for the default canvas and colors. Custom canvas, background, primary color or base title-bar height in `--tokens` use the requested design parameters to draw these elements. Do not install Python packages globally.

   Windows (from the Skill directory):
   ```powershell
   .venv/Scripts/python scripts/scientific_ppt.py doctor
   .venv/Scripts/python scripts/scientific_ppt.py validate tests/fixtures/demo/demo.json
   .venv/Scripts/python scripts/scientific_ppt.py build tests/fixtures/demo/demo.json --output artifacts/my-deck --strict
   ```
   Linux/macOS: replace `.venv/Scripts/python` with `.venv/bin/python`.

5. Read `qa_report.json` and inspect **every actual rendered preview**, using the contact sheet only for overview. Compare against the supplied references. Check text fit, captions, formula glyphs, image crops, table continuity, arrow paths, visual balance and consistency. Apply [finished-copy and emphasis rules](references/style_guide.md#成品文案与单页强调色). Put AI assistance and production disclosures in PowerPoint speaker notes via the slide JSON `notes` field. Store source details in notes on all slide types, with full bibliography entries on a dedicated references slide. Do not render source or production annotations as footer text. Keep figure/table captions, equation numbers and slide numbers; explain necessary data conditions in the relevant caption or method content. Use only one keyword highlight color per page, including highlighted body subheadings and figure annotations. Semantic chart colors and fixed template colors remain independent. Read [visual QA](references/visual_qa.md) for report interpretation and repair limits. Change content allocation/layout rather than reducing body type. The engine caps repair attempts. Limit your own additional manual repair cycles to three, then report unresolved issues.
6. Deliver the PPTX, previews and a concise limitations report. Include the editable JSON when useful. A successful PPTX export or zero geometric errors alone is not visual approval. If no renderer is available, provide the PPTX as **unverified** and explain the missing backend. Never fabricate preview images as proof of PPT rendering.

## Commands and references

- `extract source.pdf --output artifacts/source.txt`: extract text from PDF/DOCX/MD/TXT; Agent still reads figures.
- `analyze reference_directory --output artifacts/reference-study`: analyze every PPT/PPTX with structure and actual renders. Review provisional token candidates before adopting them.
- `plan outline.md --output artifacts/deck.json`: deterministic heading/paragraph intake only.
- `build deck.json --output artifacts/deck [--tokens custom_tokens.json] [--max-repairs 2]`: native PPTX with actual preview when possible.
- `render deck.pptx --output artifacts/previews [--backend libreoffice]`: actual PPT rendering.
- [Architecture](references/architecture.md): module boundaries and chosen dependencies.
- [Diagrams and equations](references/graphics.md): graph routing, LaTeX coverage and editability boundaries.
- [Figure tool selection](references/figure_tools.md): default tools by figure type and optional dependencies.
- [Test results](references/test_report.md): executed validation and known limitations.

Keep outputs local unless the user authorizes publication. Supplied references are stylistic evidence; do not redistribute their images, logos or text without appropriate rights.
