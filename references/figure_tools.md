# 科研图选库规则

按每张图的任务、原始数据和交付格式选工具。跨学科汇报可以在同一套 PPT 里混用。例如，医学影像模型架构用 Drawlib，模型评估曲线用 Matplotlib，临床队列生存曲线用 lifelines。

| 图的用途 | 首选或可选工具 | 选择依据 |
|---|---|---|
| 计算机、人工智能、深度学习、智能运维的架构或流程 | [Drawlib](https://www.drawlib.com/en/06_diagrams/overview.html) | 用分区、定制形状、嵌图和连线组合方法总览或模块详图。操作顺序和决策可用标准流程图。 |
| 可编辑模块和连线 | 原生 PPT `diagram` | 按用户要求在 PowerPoint 中保留独立模块与连线。插入整张 SVG 时，它作为单个图片对象。 |
| 通用统计图、实验曲线、频谱、等值线和矢量场 | [Matplotlib](https://matplotlib.org/stable/plot_types/index.html) 或原生 PPT 图表 | 使用输入数据和正确的轴、单位、误差定义。需在 PPT 内改数据时优先支持对应类型的原生图表。 |
| 数学函数或符号推导 | [SymPy](https://docs.sympy.org/latest/modules/plotting.html) + Matplotlib，公式用现有 LaTeX 链 | 用表达式定义函数。检查定义域、间断点与采样分辨率。 |
| 物理模拟和电路 | [SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.solve_ivp.html) + Matplotlib，电路用 [Schemdraw](https://schemdraw.readthedocs.io/en/stable/) | 模拟参数、单位和初边值来自用户或标注的教学例子。电路使用约定符号。 |
| 化学分子结构 | [RDKit](https://www.rdkit.org/docs/source/rdkit.Chem.Draw.html) | 从核对过的结构数据生成二维分子图，检查键型、电荷与立体化学。 |
| 生物和医学数据图 | [Biopython Phylo](https://biopython.org/wiki/Phylo)、[lifelines](https://lifelines.readthedocs.io/en/stable/fitters/univariate/KaplanMeierFitter.html)、Matplotlib | 分别用于进化树、生存曲线与常规数据可视化。检查树的分支定义、生存数据的删失标记和图注。 |
| 地理地图 | [GeoPandas](https://geopandas.org/en/stable/docs/user_guide/mapping.html) + [Cartopy](https://cartopy.readthedocs.io/stable/) | 前者处理矢量地理数据，后者负责地图投影。保留坐标参考系、单位和数据来源。 |

## 先决定图要解释什么

- **系统大图**适合由汇报人对着完整结构讲解。先画清输入、关键阶段、中间表示、分支、汇合和输出。保留真实存在的跨层依赖与反馈。用对齐和均衡间距组织整图，再用闭合轮廓标明阶段的归属。给图分配整页主体。大图可以包含多个局部机制，仍服务于一个完整解释任务。
- **方法总览**交代从输入到结果的主线。把训练、推理等阶段各自的处理对象圈在边界内，在框内或贴边写阶段名。共享输入、输出与汇合模块可放在相应框外，箭头从实际出入口穿过边界。用线型、线宽或箭头轮廓区分关系。
- **模块详图**展开一个机制。明确数据在什么位置分支、变换和汇合。可以用 token 条带表示序列、网格表示矩阵、错位堆叠表示特征图，用乘法节点表示门控。用颜色或编号复用算子图例，在线上只标有助于理解的张量名或尺寸。
- **步骤流程图**适用于操作顺序、条件判断或交接。采用白底节点，使用同一组有含义的图标。复杂图中，张量、波形、设备外形等本身就是辨识标记。相同对象在同一张图里保持同一种画法。

动手前确定三个问题：读者首先从哪里看起？哪个中间表示最能解释方法？哪一条分支或反馈必须单独走线？依据原材料先排分区和关键对象，再手动安排连线端点、折点及标注。主路径顺着阅读方向，支路和反馈沿可区分的路径走。为数据或语义服务的形状才使用立体堆叠、嵌图或局部放大。

例如，振动故障诊断可以排成「设备、采样波形与切窗」→「特征层、时频矩阵与训练反馈」→「分类器与诊断结果」。Mamba 模块可以从 token 条带出发，用不同形状区分内容分支和门控分支，展开时间方向的状态更新，最后在乘法节点汇合。根据来源标注示意、合成或实测数据。

## 先对齐，再定图幅

- **对齐先于装饰。** 先定阅读方向和公共基准线。同级分组对齐外缘和标题基线，平行分支对齐对应阶段的节点与端口，统一同类间距。上下两行共享一个处理阶段时，先把这个阶段排在同一列，再布置汇合与分支的走线。用间距区分层次，最后定线宽、颜色与箭头样式。
- **论文单图按阅读顺序和栏宽定比例。** 横向流程在按最终栏宽缩放后仍可读时，可以保持长图，必要时考虑跨双栏。并列分支多时，可按同一列基准上下排布。确认实际印刷或 PDF 显示尺寸下的标签和线宽，再按目标刊会要求导出并保留矢量源文件与绘图脚本。
- **横向位置有含义时，先试长图。** 时间轴、连续处理阶段、逐列对照等结构依赖横向阅读。保留横排，等比放到目标栏宽或幻灯片可用宽度，检查最小标签、箭头和图例在最终尺寸下是否易读。
- **关系适合分层时，先试接近 4:3 的构图。** 有上下并行支路、反馈回路、分层架构或成组对照时，按公共列网格对齐节点和端口，让上下空间也承载信息。4:3 是试排起点。具体尺寸由内容和可用正文区决定，图注、标题和页脚应各自留出空间。
- **两种排法都成立时，看最终成图。** 用实际栏宽或正文框等比试排。优先保留最小标签更易读、分支交叉更少、对应关系更易追踪的一版。长图过密时，可以先把可独立的支路上下排布。横向顺序必须连续且缩放后仍难读时，可保留全图并增加局部详图。
- **独立长图页上下居中。** 4:3 页面可全宽等比放置长图。将图和贴近的图注作为整体，在标题带下方至页脚上方的可用正文区内垂直居中，平衡上下留白。有配套导语时，以导语下方为图组可用区的起点，并让图组与导语保持紧邻。

## 完整大图、规整结构与细节控制

以下是本 Skill 的绘图执行规范；其中尺寸与颜色是可调整的起点，不是论文风格的统一模板。

1. **先完整，再局部。** 对系统或方法先列出对象和关系，检查图中能否追踪一条完整输入到输出的路径，以及必要的旁路、共享输入、反馈或比较关系。不要为了凑复杂度添加未经来源支持的节点或箭头。局部图用于解释确有必要展开的机制，不能代替整套系统的结构。
2. **先规整，再拆图。** 按交付用途定图幅，优先对齐节点、分组和图例。以最外侧标题、节点、箭头和图例为准收紧画布。合并过大的行距、阶段框内空带和不用的走线区，留出标签避让与区分结构所需的间距。放入 PPT 后，区分图内留白与页面留白，按上面的长图规则调整图组位置。完整系统重排后仍不可读时，保留总图并增设细节图。
3. **连线尽量直接。** 无障碍时用直线或斜线；绕开邻近文字时用轻微弧线或短折线。贝塞尔控制点尽量靠近端点连线，只偏移到足以避让障碍。长回路仅用于确实跨区的反馈，不为展示曲线而绕外圈。先选择朝向对端的边界端口，再调整节点位置、走线和标签位置。方向不同的边可分开端口，避免汇合处成为线团。
4. **文字是连线障碍物。** 在最终输出尺寸下检查每条边的线身、箭头尖端与标签。为文字包围盒留出间隙，建议以最终字号的约半个字高作为初始避让量，再按预览调整。线标签靠近所指连线，不能压在线上；文字与图标也不能遮住箭头尖端。需要经过文字所在区域时重排或改路，不用白色文字底板遮断线条来掩盖问题。交叉不可避免时明确它是交叉还是汇合。
5. **图形主导，标签常规字重。** 图内节点名、边标签、刻度、图例默认不加粗；这一规则独立于 PPT 正文和表格的加粗规则。文字保留对象名、必要变量、单位和关键操作，不在图内重复页标题、图注或整段解释。整图只需一份外部图注，PPT 中的来源放备注；讲述性说明可放演讲备注。
6. **图标按语义放置。** 模块图标可放节点旁；日志、消息、特征、数据库等对象也可用小图标放在箭头旁，表示传递的数据或外部资源，不必再包一层方框。相同对象沿用同一画法、线宽和视觉尺寸，采用简洁线描或扁平矢量风格。不要让每个节点都重复配一个装饰图标。图标库不足时可用 Drawlib 基本形状或自绘 SVG 补充，保持统一风格并记录外部素材来源。
7. **图例参与整图排版。** 先尝试在图的上方或下方居中，或与绘图区右边界对齐；按实际视觉重心选择。图例紧凑、有序且不压内容，不随意塞在剩余空白中。色块用较浅填充和清晰边界，文字仍用深色常规字重；图例符号、颜色、线型必须与图中对象一致。
8. **按成品写标签。** 图内使用具体对象名、变量、单位和简洁图注。把 AI 辅助和制作说明写入 PPT 演讲者备注。数据性质按[成品文案规范](style_guide.md#成品文案与单页强调色)说明。独立图作为一页处理，关键词强调只用一种颜色，嵌入幻灯片后与该页强调色一致。节点填色和数据系列仍可按语义使用多色。

## 箭头、圆角与阶段边界

- **按关系选择线型。** 细实线可用于顺序边和常规数据流，细虚线可用于引用或跨组对应。局部需要强调时，可使用空心或彩色实心箭头，按语义和可读性决定线宽。同图允许混用。用图例或近邻标签说明特殊样式的含义。
- **细箭头也使用尖角。** 箭杆端部平直，箭头为清楚的三角尖端，直角折点清晰。可用 Drawlib `arrow` / `arrow_polyline`，设置 `shape_r=0` 并分别控制箭杆宽度和箭头尺寸。短连线要留出清楚的箭身和三角尖端。虚线用平头线段，曲线沿弧长均匀分段。投影尺寸下检查实线、虚线及空心轮廓是否易辨。
- **圆角矩形用于操作和事件节点。** 参考 Nezha 图 5 的圆角条带，角弧轻而清晰，保留长直边。圆角半径可从节点短边的约 12–20% 试起，同类节点使用一致的圆角。较大的分组框用更克制的圆角，圆角大小以最终图尺寸和框内留白为准。以上比例为重绘起点。
- **用外框圈出阶段和归属。** 参考图 2 的服务日志组、图 5 的变换前后组和图 6 的跨度组。外框只用于需要表达归属的对象，留出标题和进出线空间。同一张图的分组外框统一选择一种体系：彩色实线框，或统一虚线框；不要在同图混用两种分组外框。彩色实线框用比内部节点边框更粗的描边，按最终投影尺寸可从约1.5–2pt试起，颜色清楚但不压过内容。此规则针对分组外框，不限制内部节点边框或箭头的虚实样式。仅在对象较少且外形适合时用椭圆圈组。框内或靠边放简短阶段名，跨框的箭头直接连接相关对象。避免用通栏阶段标题和一条横线代替分组，也避免用宽大的底色条包围空白。输入、输出或跨阶段共享组件按真实归属放置。同级横排框对齐上下边缘，竖排框对齐左右边缘，标题基线、间隔和圆角一致。先重排成员再画框；若无法对齐且框并非必需，就取消外框，用邻近关系和局部标签表示归属，不逐块套框。不同图可以交替采用彩色实线框与虚线框，避免整套文稿重复同一种围框。

Drawlib 的原生块箭头可直接画出空心箭身。下面的坐标和宽度只是起点，需根据入稿尺寸调整；空心、彩色实心、虚线的图例必须使用与正文相同的画法。

```python
from drawlib.shapes import arrow
from drawlib.styles import Styles

arrow((10, 50), (30, 50), tail_width=3, head_width=7, head_length=5,
      style=Styles.Neutral.patch(shape_r=0, shape_fill_color="#FFFFFF",
                                 shape_line_color="#A6474D",
                                 shape_line_width=1.8))
```

## 数据量、图型与配色

- 中等数据量且需要逐项查数、比较精确值时用表格；大量观测、分布、趋势和多组比较优先用数据图。表格分页是能力保障，不是每套 PPT 的内容目标。少量数据可保留为紧凑表格或简洁比较图，不强行撑成空旷的大图。不要添加虚构测量点来增加密度；图型也取决于比较任务，不只取决于行数。
- 多组数据可以用共用图例、统一坐标的子图组织。不能把不相关的指标拼在一起填空；大量系列时优先分组或小多图，避免堆成难辨识的彩线。
- 白底、浅网格、深色轴文字；系列颜色比原深蓝/深绿配色柔和，但保持线和标记可辨。参考 [ECharts 官方配色示例](https://echarts.apache.org/handbook/en/concepts/style/)，本项目选用 `#7289AB`、`#8DC1A9`、`#E69D87`、`#EEDD78`、`#DD6B66`、`#73B9BC` 作为起始系列色，记录在 `design_tokens.json` 的 `charts.palette` 中。这是从示例选出的项目调色板，不宣称是某版本的默认主题，也不增加 ECharts 运行依赖。
- 图例符号跟随系列色，不能只把图例调浅而让图中颜色保持不变。浅黄色等细线在白底不清楚时，换用更深的同色、增加标记轮廓或改用其他系列色；不要一味降低透明度。折线同时用空心圆、方块、三角或线型辅助区分；热图按有序、发散或分类变量选择色标，不能直接套分类调色板。

### 概念图

- **按比较关系排版。** 图 2 对齐展示日志关联前、关联过程和关联后，并用闭合边界圈出不同服务。图 4 将无故障构建期与生产期上下排列，在排名处汇合。图 7 并排对照同类请求，用弧线指向发生替换的子路径。重绘时用可辨的箭头类型表达对应关系。
- **给数据与算子不同的形状。** 图 4 用小型节点图展示事件、事件图和被提取的模式，用矩形表示执行处理的模块。图 6 用薄的色块表示事件类型，虚线框表示 Span 事件组。图 8 展示候选列表如何合并成异常图，再保留根模式。局部加框和用色应对应实际含义。
- **保留可读的证据样本。** 图 1 放入指标曲线、调用条带和日志字段，图 9 用实际界面展示候选证据，图 10 对照插桩前后的代码。可在 PPT 中缩减记录数量，保留足以读懂的字段、事件、数值或代码。
- **按边的含义选择线形。** 顺序边用尖角细箭头，分支或斜向相邻节点可直接连斜线，跨分区、反馈或对应关系可用贝塞尔曲线绕开文字。需要沿泳道或穿过固定端口时用直角折线。同图存在不同关系时用线型、图例或标注区分，交叉处保持方向清晰。

Drawlib 0.3.9 的 `line(start, end, style=..., arrow_head="->")` 支持任意角度。用 `line_curved(..., bend=...)` 画快速弯箭头，用 `line_bezier1(start, end, cp, ...)` 或 `line_bezier2(start, end, cp1, cp2, ...)` 精确放置控制点。原文图 6 的跨组连接和图 7 的对照箭头适合分别设置控制点。

### 数据图

- **横轴按原变量表达。** 图 3 用时间轴和故障区段组织数据，用叉号、星号和三角标记各类异常发生的时间。事件发生图保留时间位置，避免画成虚构的连续幅值曲线。
- **保留可追溯的测量点。** 图 11 用细线、空心标记、简洁坐标轴和浅横网格，显示不同事件数量下的诊断耗时。图 12 同时用线色和标记形状区分数据集与指标，横轴保留实际阈值。数据不等距时按数值定位刻度和采样点，连线只连接已核对的观测。
- **突出对比本身。** 绘图区用白底，图例紧凑且避开数据，轴名包含单位，结论写在图注或幻灯片正文。跨子图比较时统一量纲、刻度或明确标注不同范围。对于分类方法的精确比较，可像原文表 3、表 4 一样保留表格，配图只选能回答当前问题的对照。

## 按需执行

1. 根据实际图形要求选工具，明确输入来源、输出格式和编辑要求。学科名称仅供初选。例如深度学习的张量流用 Drawlib，损失曲线用 Matplotlib。
2. 先检测可选库是否可用。例如在选定解释器内用 `importlib.util.find_spec("drawlib")`。只有选中的绘图脚本导入对应库。Drawlib 的独立环境见[安装说明](installation.md#可选绘图库)，其它工具按需核对官方安装指引与版本。
3. 生成图及其可复现源码。用 JSON 的 `image` 块放置 SVG 或 PNG，需要原生编辑时用 `diagram` 或 `chart` 块。Drawlib 示例会将中文和图标转为矢量路径，并将 SVG 画布尺寸改为像素数值，以兼容项目预览链。
4. Drawlib 不可用时，方法总览可以用 SVG 组合矢量形状和真实图件，简单关系可使用原生 PPT `diagram` 块。数据图按图表类型使用上表的工具。专用科学图优先使用用户提供的原图或经验证的同类工具。记录所用工具、版本和必要的降级。
5. 先看完整单图，再按最终论文栏宽或 PPT 投影尺寸检查对齐、主路径、反馈方向、图例、字体和数据标注。逐条检查箭头与文字、图标的距离，缩览检查整图结构与空洞。如果图看起来只是一串可以随意改名的方框，回到原材料，找出需要画出具体形态的输入、中间结果或输出。先重排完整系统，确实过密再增加局部详图。保留绘图源码和数据参数。详见[单图验收](visual_qa.md#单图验收)。

选库发生在 Agent 的图件准备阶段。当前已跑通 Drawlib 示例、通用 SVG 入稿与原生 PPT 工作流。表中的其它专业工具是按需选项，使用时逐项验证。
